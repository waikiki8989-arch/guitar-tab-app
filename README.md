# Guitar Tab App

Flaskで動くギターTAB作成アプリです。コード・フレット入力からのTAB生成に加え、
ピアノ譜のMusicXMLをアップロードして音符情報を確認し、メロディーの選択とコード進行の編集ができます。

## 起動

Python 3.11以上を使用します。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

ブラウザで `http://127.0.0.1:5000` を開きます。
`app.py` の起動方法はローカル開発用です。

## MusicXMLの読み込み

1. 「ピアノ譜を読み込む」で `.musicxml` または `.xml` を選びます。
2. 「音符を読み込む」を押します。
3. 音名・開始位置・長さ・パートID・パート名・譜表・声部・小節を確認します。

動作確認には、自作の `tests/fixtures/simple_piano.musicxml` を使用できます。
2小節のピアノ譜で、左右の譜表、休符、和音、臨時記号、三連符を含みます。
解析結果は10音です。1小節目のC4とC3は開始位置0、E4は2、
2小節目の和音と左手のC3は4、三連符は5・16/3・17/3になります。

### データの扱い

- 四分音符＝1、曲の先頭＝0です。時間は `Fraction` で正確に保持します。
- 音名・記譜情報の解析はmusic21のMusicXMLインポーターを使用します。
- XMLのduration/divisionsとbackup/forwardから時間を計算し、
  元のパート・譜表・声部を保持します。
- パート名・譜表・声部の省略は `None` として保持し、画面では「未指定」と表示します。
- 小節番号は文字列として保持します。パート間は小節の出現順と最大の時間幅でそろえます。
- 休符は時間に反映しますが音符一覧には含めません。休符だけの楽譜も読み込めます。
- 反復は展開しません。タイでつながる音は記譜上の個別の音符として表示します。
- 各音符には楽譜内で一意の `note_id` を付けます。同じ楽譜の再解析でも同じIDになります。
- アップロードファイルはディスクに保存しません。

### 対応範囲

非圧縮のscore-partwise形式、2 MiB以下に対応します。
音符・休符にはduration、時間単位にはdivisionsが必要です。
外部DTDを取得せず、XMLのエンティティ定義・外部参照は拒否します。

以下は理由を表示して読み込みを中止します。

- 圧縮MusicXML（.mxl）、PDF、画像、score-timewise形式
- 装飾音、音高のない打楽器音符、transposeを持つ移調楽器の楽譜
- 時間幅を判定できない空の小節、パート間の小節数の不一致
- 不正なXML、必要な音符情報の欠落、不正な時間指定

コード推定、五線譜描画、ピアノ譜からのTAB変換は後続のissueで扱います。

## コード進行の読み込み・編集

MusicXMLの `harmony` を読み込み、ルート・コード種別・指定ベース音と
曲の先頭からの開始位置を表示します。コード記号がない場合も手入力できます。
音符からコードを推定する機能はまだありません。

1. 楽譜を読み込み、「コード進行」を確認します。
2. 「コードを追加」でコード名、小節、小節内位置を入力します。
3. 既存のコードは一覧の「変更」で入力欄に呼び出し、「変更を反映」を押します。
4. 不要なコードは「削除」を押します。

小節内位置は先頭＝0、四分音符＝1です。`1.5` や `1/3` も指定できます。
小節の長さ以上の位置は指定できません。次の小節の先頭は、その小節の0を選びます。
小節番号が重複する場合も開始位置の表示で区別できます。
音符のない休符だけの小節にもコードを配置できます。

### 対応する記号

- メジャー・マイナー：`C`、`Am`
- セブンス：`G7`、`CM7`（`Cmaj7`も受け付け、`CM7`に統一）、`Dm7`
- その他：`Bdim`、`Caug`、`Dsus4`
- ルートとベースのシャープ・フラット：`F#m7/C#`、`BbM7/F`（入力時は♯・♭も可）
- 分数コード：`C/E`、`Dm7/G`
- 和音なし：`N.C.`（`NC`も入力可）

未対応のコード種別・度数変更・多重和音・機能和声などは「未対応」と表示し、
取得した元XMLを残します。指定ベース音がなく非ゼロのinversionだけで転回形を示す場合も、
現段階では未対応です。未対応コードは元の記号を維持したまま位置だけ変更するか、
対応するコード名を入力して置き換えられます。

### 配置と元データ

- コードは次のコード位置まで、最後は曲の終わりまで有効です。
- 最初のコードより前は「コード未設定」、明示的な無和音は「N.C.」と区別します。
- 同じ位置の同じコードは編集後の進行で1つにまとめます。
- 同じ位置の異なるコードは両方残して「要修正」と表示します。
- 削除すると前のコードの有効範囲が延びます。無和音の区間にするにはN.C.を追加します。
- 読み込み時の記号は、重複を含め `ChordProgression.original` に保持します。
  編集後の進行は `events`、未設定や競合を含む有効区間は `segments` で取得できます。
- 手動で変更したコードの入力元は「手入力」に変わります。元の音符とメロディーは変更しません。
- コード進行も署名付きの作業情報で引き継ぎます。ファイルへの保存は未実装です。
- MusicXMLのoffsetは現在の時間位置にdivisions単位で加算します。
  表示用の座標属性は時間へ変換しません。

解析の参照仕様：[MusicXML harmony](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/harmony/)、
[MusicXML offset](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/offset/)。

### コード用サンプル

`tests/fixtures/chord_progression.musicxml` は3小節の自作楽譜です。
元の記号10件を読み込み、同じコードを統合した7件が表示されます。

- 開始0：C
- 開始2：G7/BとAm（競合の確認用。どちらかを削除して解消できます）
- 開始13/3：CM7（2小節目の1/3）
- 開始5：Dm7/G
- 開始7：N.C.
- 開始9：Dのmajor-ninth（未対応として元情報を表示）

曲の終わりは11です。2小節目は長さ3、ほかは長さ4です。

## メロディーの選択

1. MusicXMLを読み込みます。最初はどの音も自動選択しません。
2. 「メロディーを選ぶ」でパート・譜表・声部を選び、「条件を反映」を押します。
3. 個別にチェックして「選択を反映」を押すか、「条件に一致する音をまとめて追加」を押します。
4. 表示条件を切り替え、ほかの譜表や声部の音も追加します。
5. 「選択済みメロディー」で不要な音を「除外」します。
6. 同時発音の注意を解消したら「メロディーを確定」を押します。

チェック変更はボタンの送信時に反映します。表示条件を切り替えるときも、
直前の候補へのチェック変更を反映してから表示を更新します。
表示されていない候補の選択はそのまま保持します。選択済み一覧には全選択音を表示します。
「すべて」と「未指定」を区別して、元の譜表・声部情報が省略された音も選択できます。

元の音符は変更せず、選択したIDを `MelodySelection` で別に管理します。
開始位置・長さは維持するため、休符に相当する空白を詰めません。
同じ開始位置の複数音は注意表示し、1音に絞るまで確定できません。
長さの重なりやタイを含む高度な単旋律の判定はまだ行いません。
確定後に選択音を変更すると未確定に戻ります。表示条件の変更だけでは確定を解除しません。
後続の処理は `MelodySelection.get_confirmed_melody()` で確定した音符を取得できます。

### メロディー用サンプル

`tests/fixtures/melody_selection.musicxml` は8音を含む3小節の自作楽譜です。

1. パートP1・譜表1・声部1を選び、一括追加します（C4・E4・C5・E5の4音）。
2. 和音内のE5を除外します。
3. パートP1・譜表2・声部4を選び、一括追加します（D4）。
4. パートP2・譜表「未指定」・声部「未指定」を選び、一括追加します（G4）。
5. 確定すると、C4・E4・C5・D4・G4の5音になります。

開始位置は0・2・4・6・8、長さは1・2・2・2・4です。
同じ譜表の別声部や和音、メロディーの譜表・パート移動、休符を確認できます。

### 作業状態の保持

- JavaScriptは不要です。画面のフォーム送信で選択・修正を行います。
- 音符と選択状態を署名付きのフォームデータとして引き継ぎます。
  cookieへの楽譜格納、サーバー上のファイル保存や共通の選択状態は使用しません。
- コード・フレットからの既存TAB生成でも、反映済みのメロディーは保持します。
- 新しいMusicXMLの読み込みに成功すると選択をリセットします。
  通常のファイル解析エラーでは現在の作業を保持します。
- 新しくページを開くときは楽譜の再読み込みが必要です。
  最後の応答から8時間経過した作業情報も期限切れになります。
- 初期設定の署名鍵は起動ごとに生成するため、サーバー再起動後は楽譜の再読み込みが必要です。
  複数プロセスで運用する場合は、共通の十分にランダムな `GUITAR_TAB_SECRET_KEY` を環境変数に設定します。
- ファイルへの保存・再読み込みは後続のissueで実装します。
