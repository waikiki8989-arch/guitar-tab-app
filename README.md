# Guitar Tab App

Flaskで動くギターTAB作成アプリです。コード・フレット入力からのTAB生成に加え、
ピアノ譜のMusicXMLをアップロードして音符情報を確認し、メロディーの選択とコード進行の編集、
選択したメロディーの五線譜・TAB表示、運指編集、ベース・伴奏を追加するソロギター編曲・確認再生ができます。
作業途中の内容をJSONプロジェクトとして保存し、元のMusicXMLなしで編集を再開できます。

## 起動

Python 3.11以上を使用します。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

ブラウザで `http://127.0.0.1:5000` を開きます。
`app.py` の起動方法はローカル開発用です。

## MusicXMLの読み込み

1. 「ピアノ譜を読み込む」で `.musicxml` または `.xml` を選びます。
2. 「音符を読み込む」を押します。
3. 音名・開始位置・長さ・パートID・パート名・譜表・声部・小節を確認します。

動作確認には、自作の `tests/fixtures/simple_piano.musicxml` を使用できます。
2小節のピアノ譜で、左右の譜表、休符、和音、臨時記号、三連符を含みます。
解析結果は10音です。1小節目のC4とC3は開始位置0、E4は2、
2小節目の和音と左手のC3は4、三連符は5・16/3・17/3になります。

### データの扱い

- 四分音符＝1、曲の先頭＝0です。時間は `Fraction` で正確に保持します。
- 音名・記譜情報の解析はmusic21のMusicXMLインポーターを使用します。
- XMLのduration/divisionsとbackup/forwardから時間を計算し、
  元のパート・譜表・声部を保持します。
- パート名・譜表・声部の省略は `None` として保持し、画面では「未指定」と表示します。
- 小節番号は文字列として保持します。パート間は小節の出現順と最大の時間幅でそろえます。
- 休符は時間に反映しますが音符一覧には含めません。休符だけの楽譜も読み込めます。
- 反復は展開しません。タイでつながる音は記譜上の個別の音符として表示します。
- 各音符には楽譜内で一意の `note_id` を付けます。同じ楽譜の再解析でも同じIDになります。
- アップロードファイルはディスクに保存しません。

### 対応範囲

非圧縮のscore-partwise形式、2 MiB以下に対応します。
音符・休符にはduration、時間単位にはdivisionsが必要です。
外部DTDを取得せず、XMLのエンティティ定義・外部参照は拒否します。

以下は理由を表示して読み込みを中止します。

- 圧縮MusicXML（.mxl）、PDF、画像、score-timewise形式
- 装飾音、音高のない打楽器音符、transposeを持つ移調楽器の楽譜
- 時間幅を判定できない空の小節、パート間の小節数の不一致
- 不正なXML、必要な音符情報の欠落、不正な時間指定

選択した単旋律はギター運指とTABに変換し、ベース・伴奏を追加できます。

## コード進行の読み込み・編集

MusicXMLの `harmony` を読み込み、ルート・コード種別・指定ベース音と
曲の先頭からの開始位置を表示します。コード記号がない場合も手入力できます。
コード記号がない場合は、後述の「音符からコード候補を探す」も利用できます。

1. 楽譜を読み込み、「コード進行」を確認します。
2. 「コードを追加」でコード名、小節、小節内位置を入力します。
3. 既存のコードは一覧の「変更」で入力欄に呼び出し、「変更を反映」を押します。
4. 不要なコードは「削除」を押します。

小節内位置は先頭＝0、四分音符＝1です。`1.5` や `1/3` も指定できます。
小節の長さ以上の位置は指定できません。次の小節の先頭は、その小節の0を選びます。
小節番号が重複する場合も開始位置の表示で区別できます。
音符のない休符だけの小節にもコードを配置できます。

### 対応する記号

- メジャー・マイナー：`C`、`Am`
- セブンス：`G7`、`CM7`（`Cmaj7`も受け付け、`CM7`に統一）、`Dm7`
- その他：`Bdim`、`Caug`、`Dsus4`
- ルートとベースのシャープ・フラット：`F#m7/C#`、`BbM7/F`（入力時は♯・♭も可）
- 分数コード：`C/E`、`Dm7/G`
- 和音なし：`N.C.`（`NC`も入力可）

未対応のコード種別・度数変更・多重和音・機能和声などは「未対応」と表示し、
取得した元XMLを残します。指定ベース音がなく非ゼロのinversionだけで転回形を示す場合も、
現段階では未対応です。未対応コードは元の記号を維持したまま位置だけ変更するか、
対応するコード名を入力して置き換えられます。

### 配置と元データ

- コードは次のコード位置まで、最後は曲の終わりまで有効です。
- 最初のコードより前は「コード未設定」、明示的な無和音は「N.C.」と区別します。
- 同じ位置の同じコードは編集後の進行で1つにまとめます。
- 同じ位置の異なるコードは両方残して「要修正」と表示します。
- 削除すると前のコードの有効範囲が延びます。無和音の区間にするにはN.C.を追加します。
- 読み込み時の記号は、重複を含め `ChordProgression.original` に保持します。
  編集後の進行は `events`、未設定や競合を含む有効区間は `segments` で取得できます。
- 手動で変更したコードの入力元は「手入力」に変わります。元の音符とメロディーは変更しません。
- コード進行も署名付きの作業情報で引き継ぎ、プロジェクトファイルに保存できます。
- MusicXMLのoffsetは現在の時間位置にdivisions単位で加算します。
  表示用の座標属性は時間へ変換しません。

解析の参照仕様：[MusicXML harmony](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/harmony/)、
[MusicXML offset](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/offset/)。

- 開始2：G7/BとAm（競合の確認用。どちらかを削除して解消できます）

## 音符からコード候補を推定する

1. MusicXMLを読み込み、「音符からコード候補を探す」を開きます。
2. 解析するパート・譜表を選びます。初期設定の「すべて」は伴奏を含む元の楽譜全体です。
3. 「コード候補を推定・再推定」を押すと、1小節ごとに最大3候補を表示します。
4. 小節途中のコード変更には、対象小節を選び、分割位置を入力して再推定します。
   例えば長さ4の小節を前半・後半に分ける場合、分割位置は `2` です。
5. 必要なら開始・終了を指定して小節の一部だけを解析できます。空欄は小節全体です。
   小節内位置は先頭＝0、四分音符＝1で、`1/3` などの分数も入力できます。
6. 候補と一致する音・コード外の音・不足する構成音を確認し、「この区間に採用」を押します。
7. 既存コードが有効な区間では、表示された置き換え対象を確認してチェックを入れます。
8. 候補を使わない場合は「この区間は見送る」を押すか、コード進行で手入力します。
   見送りを解除するには再推定します。

### 推定の方法と範囲

- `chord_estimation.py` のルールベース処理です。外部AI・外部APIは使用しません。
- メロディーの選択状態には依存せず、指定したパート・譜表の元音符を集計します。
- 開始前から伸びている音も対象です。発音時間は解析区間内に切り詰めて集計します。
- タイ情報は `ScoreNote.tie` に保持します。推定時は同じパート・譜表・声部・音高で
  時間が連続するタイを接続します。元の記譜上の音符と音符IDは変更しません。
- 対応コードの接尾辞と構成音は `chord_progression.CHORD_DEFINITIONS` に共通化しています。
- オクターブ違いをまとめた音の種類が3つ未満の場合、候補を出しません。
- 候補には最低3種類の構成音の一致と、発音時間で重み付けした一致率が2/3以上必要です。
- 順位は一致・不一致の発音時間と不足する構成音で決め、最低音がルートなら少し優先します。
  最低音だけでルートを決めません。ルートと最低音が違う場合は分数コードを提示します。
- 内部の順位付けは `2 × 一致時間 / 全時間 − 1 − 不足音数 / 5` に、
  最低音とルートが一致した場合の `1/20` を加算します。同点時も同じ順で提示します。
- 表示される順位は正解の確率ではありません。調性・前後のコード・高度な和声解析は未対応です。
- 無音や根拠不足では理由を表示します。微分音を含む区間も現在は推定対象外です。

### 採用と区間外の保持

- 推定・再推定・見送りでは、コード進行やメロディーを変更しません。
- 採用した候補の入力元は「推定候補から採用」です。後から手動修正できます。
- 候補を採用する区間内のコードだけを変更します。
  既存コードが区間より前から継続している場合も、置き換え対象として表示します。
- 区間の終わりにコード変更がなければ、元のコードをそこで復元します。
  元が未設定の場合は「コード未設定」の境界を追加し、N.C.とは区別します。
- 元の状態が未対応コードや競合だった場合も、区間外ではその状態を保持します。
- 復元した行は入力元に「区間後に復元」と表示します。未設定の境界も一覧に表示します。
  境界を削除すると直前のコードが先へ延びるため、採用範囲を保ちたい場合は残してください。
- 推定設定と見送り状態は既存の署名付き作業情報で引き継ぎます。
  新しい楽譜の読み込みに成功するとリセットします。未採用の候補・推定設定・見送り状態は
  プロジェクトファイルへの保存対象外です。採用したコードは保存します。

## メロディーの選択

1. MusicXMLを読み込みます。最初はどの音も自動選択しません。
2. 「メロディーを選ぶ」でパート・譜表・声部を選び、「条件を反映」を押します。
3. 個別にチェックして「選択を反映」を押すか、「条件に一致する音をまとめて追加」を押します。
4. 表示条件を切り替え、ほかの譜表や声部の音も追加します。
5. 「選択済みメロディー」で不要な音を「除外」します。
6. 同時発音の注意を解消したら「メロディーを確定」を押します。

チェック変更はボタンの送信時に反映します。表示条件を切り替えるときも、
直前の候補へのチェック変更を反映してから表示を更新します。
表示されていない候補の選択はそのまま保持します。選択済み一覧には全選択音を表示します。
「すべて」と「未指定」を区別して、元の譜表・声部情報が省略された音も選択できます。

元の音符は変更せず、選択したIDを `MelodySelection` で別に管理します。
開始位置・長さは維持するため、休符に相当する空白を詰めません。
同じ開始位置の複数音は注意表示し、1音に絞るまで確定できません。
長さの重なりやタイを含む高度な単旋律の判定はまだ行いません。
確定後に選択音を変更すると未確定に戻ります。表示条件の変更だけでは確定を解除しません。
後続の処理は `MelodySelection.get_confirmed_melody()` で確定した音符を取得できます。

1. パートP1・譜表1・声部1を選び、一括追加します（C4・E4・C5・E5の4音）。
2. 和音内のE5を除外します。
3. パートP1・譜表2・声部4を選び、一括追加します（D4）。
4. パートP2・譜表「未指定」・声部「未指定」を選び、一括追加します（G4）。
5. 確定すると、C4・E4・C5・D4・G4の5音になります。

開始位置は0・2・4・6・8、長さは1・2・2・2・4です。
同じ譜表の別声部や和音、メロディーの譜表・パート移動、休符を確認できます。

### 作業状態の保持

- 選択・修正はJavaScriptなしでも画面のフォーム送信で行えます。五線譜・再生にはJavaScriptが必要です。
- 音符と選択状態を署名付きのフォームデータとして引き継ぎます。
  cookieへの楽譜格納、サーバー上のファイル保存や共通の選択状態は使用しません。
- コード・フレットからの既存TAB生成でも、反映済みのメロディーは保持します。
- 現在の作業の置き換えを確認し、新しいMusicXMLの読み込みに成功すると選択をリセットします。
  通常のファイル解析エラーでは現在の作業を保持します。
- 新しくページを開くときは、保存済みプロジェクトまたは楽譜を読み込んでください。
  最後の応答から8時間経過した作業情報も期限切れになります。
- 初期設定の署名鍵は起動ごとに生成するため、サーバー再起動後は作業中の画面の情報が期限切れになります。
  保存済みプロジェクトは署名鍵に依存せず、新しい画面から開いて再開できます。
  複数プロセスで運用する場合は、共通の十分にランダムな `GUITAR_TAB_SECRET_KEY` を環境変数に設定します。
- 作業を残すには下記の「プロジェクトの保存・再読み込み」を使用してください。

## 五線譜表示・確認再生

1. MusicXMLを読み込み、メロディーの音を選んで選択を反映します。
2. 未確定の間は「メロディーとコードの五線譜・確認再生」に元の音高で表示します。
   メロディーを確定すると「ギター五線譜・TAB編集・確認再生」に切り替わります。
3. 「再生する音」でメロディーのみ／メロディーとコードを選び、「再生」を押します。
4. 「一時停止」はその位置を保持し、「停止」は先頭に戻します。曲の終わりでも停止します。
5. 再生速度は0.5〜2倍に変更できます。音の高さは変わりません。
6. コードやメロディーの編集を始めると再生を停止します。変更を反映すると楽譜も更新されます。

表示は同梱のOpenSheetMusicDisplay 2.1.2、音声はWeb Audio APIを使用します。
外部サービスへの楽譜送信や音源のダウンロードは行いません。
再生中は現在位置をカーソルで示します。カーソルは音符・休符の開始位置ごとに移動します。

- 未確定の選択もプレビューできますが、発音時間が重なる選択は表示・再生できません。
- 元の音高・開始位置・長さを保持し、空白には休符を補います。付点・タイ・三連符に対応します。
- 弱起、途中の拍子・調号・テンポ変更を反映します。省略時は4/4、調号なし、四分音符＝100です。
- タイでつながった音は再発音しません。コードなどの変更位置では表示上の音符を分割することがあります。
- 伴奏はコード構成音と低音を伸ばす簡易音です。分数コードは指定ベース音を低音に使います。
- 未対応・競合コードは記号と注意を表示して伴奏を鳴らしません。未設定・N.C.も無音です。
- 反復は展開しません。強弱・特殊奏法・元のページ配置は再現しません。
- 特殊な拍子・調号や三連符以外の連符は制限があります。微分音・複合的な連符は未対応です。
- 確定後は下記のギター変換設定を反映してTABを併記し、ギター用の実音で再生します。

### 表示・再生の確認用サンプル

`tests/fixtures/score_playback.musicxml` を読み込み、全音をメロディーに追加します。

拍子は4/4→3/4→6/8、調号も途中で変わります。
テンポは四分音符換算で120→60→120、曲全体の長さは四分音符11個分です。
コードはC/E、Dm7/G、N.C.、未対応のE major-ninth、G7を確認できます。

ブラウザでは、楽譜と記号が表示されること、タイで音が途切れないこと、
伴奏の切り替え・一時停止からの再開・速度変更・編集時の停止を確認してください。

## メロディーをギターの弦・フレットに変換する

1. MusicXMLを読み込み、メロディーを選択して「メロディーを確定」を押します。
2. 「ギターの弦・フレットを選ぶ」に、各音の候補と自動選択された運指を表示します。
3. フレット上限（0〜24、初期値24）とオクターブ移動（変更なし／1オクターブ下／上）を選び、
   「設定を反映・運指を再計算」を押します。
4. 音符ごとの候補を選んで「運指を反映」を押すと手動変更できます。
5. 「この運指を固定する」をチェックして反映すると、再計算でもその運指を保持します。
   「固定を解除」で自動選択の対象に戻せます。解除だけでは有効な現在の選択は変えません。

標準チューニングの実音（6弦E2・5弦A2・4弦D3・3弦G3・2弦B3・1弦E4）を使います。
ギター五線譜の記譜上のオクターブ差による暗黙の移調は行いません。
元のメロディーは変更しません。確定後の五線譜・TAB・確認再生にはギター用の変換結果を反映します。
併記するギター五線譜だけは、実音より1オクターブ高い記譜になります。
小節・音符ID・開始位置・長さを保持し、休符相当の空白を詰めません。

### 自動選択のルール

- `fingering.py` で全候補を列挙し、動的計画法で運指の列を選びます。
- 第1評価は隣接する音の「フレット差×2＋弦番号差」の合計です。
  どちらかが開放弦なら、フレット移動の評価は0です。
- 第1評価が同じなら、フレット番号の合計が小さい列を優先します。
- 候補をフレット番号・弦番号の昇順に並べ、同点なら先の候補・遷移を採用するため、結果は決定的です。
- 開放弦の間の手の位置や休符の長さは評価しません。すべての奏者の弾きやすさは保証しません。
- 同じパート・譜表・声部・音高で時間が連続したタイは一組として扱い、同じ運指にします。
  手動変更・固定・解除もタイ全体に反映します。
- 未変換の音は理由付きで一覧に残し、その前後を別々に最適化します。
- 手動変更は通常の画面操作で保持します。再計算では固定した運指のみを制約にします。

### 固定・メロディー変更時の扱い

- オクターブ移動やフレット上限の変更で固定が無効になった場合は、固定情報を残して「未変換」と表示します。
  黙って別の運指には置き換えません。候補から再選択するか固定を解除してください。
- メロディーから除外した音の運指・固定は削除します。追加した音は再確定時に計算します。
- メロディーが未確定の間は運指一覧を表示しません。発音時間が重なる単旋律でない選択も変換できません。
- 新しいMusicXMLの読み込みに成功すると設定・運指をリセットします。
- 運指も署名付きフォームで引き継ぎ、プロジェクトに保存できます。カポ、変則チューニング、
  左手の指番号や奏法は今回の対象外です。

## 小節・リズム付きTABの表示と編集

1. メロディーを確定すると、上段のギター五線譜と下段の6線TABを同じ時間軸で表示します。
2. TABのフレット番号、または五線譜の音符をクリックすると、両方で同じ音が強調されます。
   キーボードのTab→Enter／Space、または「編集する音符」の一覧からも選択できます。
3. 候補を選び「TABの運指を変更・固定」を押すと、同じ実音を保ったまま弦・フレットを変更します。
4. 「TABの固定を解除」で固定を解除できます。タイで連続する音は一緒に変更します。
5. 「元に戻す／やり直す」で、このTAB編集画面の直近20件の運指変更・固定解除を戻せます。

TABは上が1弦、下が6弦です。小節線・小節番号、休符・タイ・三連符を表示します。
符尾に加えて、TAB下の「4分」「2分」などで音価を明示し、末尾の「·」で付点を表します。
コード名は対応する時間位置に表示します。長い楽譜は自動改行し、狭い画面では横スクロールできます。

**ギター五線譜は記譜より1オクターブ低く鳴ります。**
変換設定の±1オクターブ移動とは別の記譜上の差です。
再生はギター用の実音を使い、同じ音高の別運指に変更しても音高は変わりません。
再生カーソルは五線譜とTABをまたいで表示し、譜面選択・編集時には再生を停止します。

未変換音はTAB上の×と赤い枠で示し、小節・開始位置・理由を一覧表示します。
再生前に確認欄へチェックが必要で、未変換音の区間は無音になります。
音符の開始位置や長さ、元のピアノ譜の音高は変更しません。

- 編集履歴は楽譜・選択メロディー・変換設定を変更したときにリセットします。
- 下の運指一覧から変更した場合も、TAB編集の履歴をリセットします。
- コード進行の編集や譜面の音符選択だけでは履歴をリセットしません。
- 音符IDと運指を署名付き状態に保持します。SVGの見た目を編集データとして保存しません。
- メロディーの音高・音価の直接編集は対象外です。印刷・楽譜出力は下記の専用機能を使います。
  ベース・伴奏の追加は下記の編曲画面で行います。

確認には `tests/fixtures/score_playback.musicxml`（付点・三連符・タイ・途中のコード変更）と
`tests/fixtures/guitar_fingering.musicxml`（未変換音）を使えます。
OSMD 2.1.2のTABに音価・休符・選択領域を補う処理は `static/tab_editor.js` にあります。
描画ライブラリ更新時には下記のブラウザテストも実行してください。

## ソロギター編曲

1. メロディーを確定し、運指を確認して「ソロギター編曲を始める」を押します。
2. 対象小節と区間を選び、「ベースのみ」または「ベースと伴奏」の候補を作ります。
3. 候補の音・弦・フレット・注意点を確認し、「候補を含めて区間を試聴」で確認します。
   候補はまだ編曲に反映されていません。「候補を採用」または「候補を見送る」を選びます。
4. 手動では役割、小節内位置、長さ、弦・フレットを指定して音を追加できます。
   追加音は譜面上のクリック、Tab→Enter／Space、または一覧の「編集」で選びます。
   追加音の弦・フレットを変えると実音も変わります。
5. 「再生する音」の「メロディー・ベース・伴奏」で採用済みの編曲を確認できます。
   メロディーのみとの切り替え、一時停止・再開、速度変更も使えます。
6. 追加音の追加・編集・削除・候補採用は「編曲を元に戻す／やり直す」で直近20件を戻せます。

メロディー・ベース・伴奏は同じ五線譜・TAB上で黒・青・紫に分け、独立した声部として表示します。
元のメロディーの音高・開始位置・長さとコード進行は、編曲操作では変更しません。
編曲中の伴奏再生には追加音だけを使い、コード確認用の簡易和音は重ねません。

### 候補生成とチェックの範囲

- 外部AI・APIを使わない決定的なルールです。指定区間のコード変更ごとに持続音を提案します。
  分数コードでは指定ベース音を使い、「ベースと伴奏」では最大2音の構成音を足します。
- 既存のメロディー・追加音が使用している弦を避けます。後から同じ弦を使う音が始まる場合は、
  その直前まで候補の長さを切ります。既存の追加音を自動で置き換える操作はありません。
- メロディーより低い音を優先し、押弦の広がり・低いベース・低フレットなどで候補を順位付けします。
  全区間の運指を最適化するものではなく、候補にも注意箇所が残る場合があります。
- コード未設定・N.C.・未対応・競合の区間、未変換メロディーが重なる区間は候補を作らず理由を表示します。
- 同じ弦での発音時間の重複、上限を超えるフレット、コード外の音、メロディー・運指変更を表示します。
  持続音も含め、同時に押さえるフレットの最大値と最小値の差を区間ごとに確認できます。
  開放弦は広がりに含めません。目安は初期値4、0〜24に変更できます。
- 注意があっても手動編集・採用はできます。指番号、指の本数、バレーや特殊奏法は判定せず、
  演奏可能性を保証するものではありません。複雑な伴奏パターン、カポ・変則チューニングは未対応です。
- メロディー・運指・コードの変更では追加音を保持し、古い候補と編曲履歴を破棄します。
  メロディーを未確定に戻した場合は、再確定するまで編曲操作を中断します。
  「メロディー・運指の変更を確認済みにする」で比較基準を現在のメロディーに更新できます。
- 編曲状態は署名付きフォームで引き継ぎます。新しい楽譜の読み込みに成功するとリセットします。
  プロジェクトへの保存・再読み込みに対応します。楽譜・音声のエクスポートは未実装です。

確認には `tests/fixtures/score_playback.musicxml` を読み込み、全音を確定して、
対象小節「1（開始1）」で「ベースと伴奏」の候補を作れます。
先頭の弱起小節「0」はコード未設定のため候補が出ません。

## プロジェクトの保存・再読み込み

1. 「作業の保存・再読み込み」でプロジェクト名を入力し、「プロジェクト名を反映」を押します。
2. 各編集欄の変更を反映してから「プロジェクトを保存」を押します。
   `曲名.guitar-tab.json` をダウンロードするので、端末の保存先を確認してください。
3. 続きを編集するときは「プロジェクトを開く」で保存したファイルを選びます。
   元のMusicXMLや前回のサーバーの署名鍵は不要です。
4. 現在の作業がある場合は置き換えを確認します。ファイル全体の検証に成功すると、
   楽譜・編集内容を復元し、五線譜・TABを再描画します。再生は停止状態になります。
5. 復元後も同じ画面で編集・再保存できます。メロディー未選択、コード未設定、
   未確定メロディー、未変換音・無効になった固定運指・発音の衝突がある状態も保存できます。

### 変更と保存の表示

- ファイルを開いた／ダウンロード用に作成した内容から変更がある場合、画面に表示します。
  候補の生成、音符の画面上の選択、表示条件だけの変更は保存内容の変更に含めません。
- 入力中でまだ反映していない値は保存に含めません。JavaScript有効時は保存を止めて案内し、
  別のフォームを送信して入力が失われる場合も確認します。
- 別のプロジェクト・MusicXMLへの置き換えは、確認欄または確認ダイアログで承認します。
  読み込み失敗時は現在の編集内容・候補・履歴を保持してエラーを表示します。
- 未保存の変更や入力がある場合、ページを閉じる・再読み込みする際に、ブラウザが対応する範囲で
  確認を出します。ブラウザによっては、ユーザー操作がない場合や端末の強制終了時には出ません。
- 保存はダウンロード方式です。既存ファイルの自動更新、ブラウザ内への自動保存はありません。
  「ダウンロードを開始しました」は端末への保存完了を保証しません。保存先を確認してください。
- JavaScriptなしでもフォームによる保存・再読み込みはできます。保存は別タブへのダウンロードで、
  元の編集画面を保持します。この場合、画面の変更表示は保存ボタンを押しても解除しません。
  ファイル保存やページを離れる前の確認は利用者自身で行ってください。

### 保存形式

独立モジュール `project.py` でJSONの保存・検証・読み込みを行います。
UTF-8、形式識別子 `guitar-tab-project`、形式バージョン `2` です。
バージョン1のファイルも読み込めます。出力設定を初期値で補い、次回保存時にバージョン2になります。

```json
{
  "format": "guitar-tab-project",
  "version": 2,
  "project": {
    "name": "練習曲",
    "created_at": "2026-10-08T12:00:00+00:00",
    "updated_at": "2026-10-08T12:30:00+00:00"
  },
  "data": {}
}
```

上は外枠の説明です。実際の `data` には次の必須項目が入り、空のままでは読み込めません。

| 項目 | 内容 |
| --- | --- |
| `filename` | 元のMusicXMLファイル名 |
| `selection` | 元の全音符、音符ID、選択ID、メロディーの確定状態。譜表・声部・小節・タイ・連符等も含む |
| `progression` | 小節、読み込み時のコード記号、編集後のコード進行と入力元 |
| `notation` | 拍子・調号・テンポの変更と記譜上の注意 |
| `tuning` | 弦番号と開放弦の実音。標準チューニングのみ |
| `fingering` | フレット上限、オクターブ移動、運指の選択・固定と固定時の実音 |
| `export_settings` | 曲名、作曲者、編曲者、出力する譜面（五線譜＋TAB／TABのみ） |
| `arrangement` | 追加音、採番、押弦の広がりの設定、変更確認の比較基準となるメロディー。開始前は`null` |

開始位置・長さ・実音の数値は、`"1"`、`"4/3"`のような整数・分数の文字列で保存します。
時間を小数に丸めないため、三連符の位置も保存前後で一致します。
SVG・音声・署名付き作業トークンを保存せず、復元データから表示と再生を作り直します。
未採用候補・再生位置・選択中の画面・絞り込み・取り消し／やり直し履歴は保存しません。

### 読み込みの検証と制限

- プロジェクトファイルは8 MiB以下です。MusicXMLは引き続き2 MiB以下です。
  現在の作業情報を含むHTTPリクエスト全体の上限は16 MiBです。
- 必須項目・型・バージョン・重複ID・参照ID・曲の範囲・弦・フレット・音高の整合を検証します。
  JSONの重複キー、非有限数、不正な元コードXML、未対応バージョンも拒否します。
- 1配列は原則10,000件まで、小節・追加音・編曲の比較基準音は各2,000件までです。
  数値の文字列は分子・分母各16桁まで、絶対値1,000,000以下、小節の長さは1,024以下です。
- 発音時間の衝突や現在の設定に合わなくなった固定運指は、ファイル破損と区別します。
  状態を復元してから既存のチェックで注意を表示し、黙って固定を解除しません。
- ファイルはサーバーのプロジェクト一覧やデータベースに保存しません。
  アカウント、クラウド同期、自動保存、クラッシュ復旧、共同編集、音声への出力は対象外です。
  印刷・MusicXML出力は、プロジェクト保存とは別の操作です。

## 印刷・MusicXML出力（Issue #20）

1. メロディーを確定し、必要なベース・伴奏を編曲に採用します。
2. 「楽譜を印刷・出力する」で曲名・作曲者・編曲者・譜面の種類を入力し、「出力設定を反映」を押します。
   曲名が空欄ならプロジェクト名を使います。各名前は120文字以内です。
3. 「印刷プレビューを開く」または「MusicXMLをダウンロード」を押します。
   入力中の変更がある場合は、先に各欄の反映ボタンを押してください。
4. 出力前に小節・開始位置・理由を確認します。未変換音、無効な運指、同じ弦の重複発音は
   修正するまで出力できません。押弦の広がりやコード外の音などの注意は、確認欄にチェックして進めます。
5. 印刷プレビューの「印刷・PDF保存」でブラウザーの印刷画面を開きます。
   A4・縦・倍率100%、ブラウザーのヘッダー／フッターはオフにします。
   PDFは保存先の「PDFに保存」を選びます。

出力操作で編曲やプロジェクトの保存状態は変更しません。未採用のコード候補・編曲候補は含みません。
出力設定を残す場合は、反映後にプロジェクトを保存してください。復元したプロジェクトからも同じ内容を出力できます。

### 印刷の表示

専用画面に曲名・クレジット・初期テンポ・標準チューニングと楽譜を表示します。
途中のテンポ変更、コード、小節番号、休符、付点、三連符、タイも表示します。
TABの音価は数字の下にも補記し、休符は「休符」、三連符の音価には「³」を付けます。
五線譜とTABをまとめた段単位でA4のページに配置し、15 mmの余白とページ番号を付けます。
編集ボタン、選択枠、再生カーソルは含みません。表示にはJavaScriptが必要です。
記号が印刷幅を超える場合や、段が1ページに収まらない場合は、切れた譜面を出さずエラーを表示します。

### MusicXMLの構造と制限

`score_export.py` が、非圧縮MusicXML 4.0の `.musicxml` を生成します。
1つのギターパートに五線譜とTABの2譜表（またはTABのみ）を置きます。
分数時間を整数のdivisionsとdurationへ変換し、声部ごとの異なる長さを保持します。
小節・コード・記譜情報の変更位置で分割した持続音はタイで接続します。
対応するコードはharmony要素、未対応の記号は警告付きの文字情報として残します。

音高は実音で記録し、五線譜にはギター用の1オクターブ下の音部記号を使います。
TABの弦・フレットと標準チューニングは実音に一致します。
併記時のTABはalternate譜表と無音のcue音符で表し、五線譜との二重再生を防ぎます。
TABのみの場合は通常の音符として演奏されます。
仕様の根拠：
[clef-octave-change](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/clef-octave-change/)、
[staff-type](https://www.w3.org/2021/06/musicxml40/musicxml-reference/data-types/staff-type/)、
[cue](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/cue/)。

- 通常の音価・付点・完結する3:2の三連符を扱います。音価の異なる音が同じ三連符に入る場合も保持します。
  その他の連符、小節末などで完結しない三連符、微分音や正確に記譜できないリズムは、対象箇所を示して出力を停止します。
  印刷も同じ事前検査を通すため、これらのリズムは印刷できません。
- 元ファイルから読み込めなかった奏法等の注意も出力前に表示します。反復は展開せず、アプリ内の記譜順を使います。
- MuseScoreではcueのTAB数字が小さく表示される場合があります。印刷プレビューでは通常サイズです。
- 楽譜ソフトのコード自動演奏が有効な場合、コード記号から追加の伴奏が鳴ることがあります。
  編曲した音符だけを確認するときはコード自動演奏をオフにしてください。
- 出力XMLは他の楽譜ソフト向けです。作業再開には元データを保つプロジェクトJSONを使ってください。
  すべてのソフトで同じレイアウトになる保証、圧縮MusicXML、音声・MIDI出力、サーバー側PDF生成は対象外です。

### 実機検証の記録

2026-10-15、Chromium **151.0.7922.34**、OSMD **2.1.2**、MuseScore Studio **4.7.5**で確認しました。

- Chromium：32小節の五線譜＋TAB／TABのみを印刷プレビューとA4 PDFに出力。
  小節が重複・欠落せず、段がページをまたがないこと、ページ番号、操作部品の非表示を検証。
- MuseScore：MusicXMLを実際に読み込み、保存したMSCXから、全音符の実音・開始位置・長さ・タイ・TABの弦とフレットを照合。
  小節をまたぐベース、異なる音価の同時発音、混在する三連符、途中のテンポ変更を含みます。
  併記のTAB全音符が無音、TABのみの全音符が演奏対象であることも確認。
- W3C MusicXML 4.0の公式XSDで両レイアウトの構造を検証。

## テスト

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m pip check
git diff --check
```

Node.jsがある環境では、再生制御のテストも実行できます（追加のnpmパッケージは不要です）。

```bash
node tests/score_player.test.cjs
```

Pythonテストは生成したMusicXMLを再解析して音高・時間・記譜情報を確認します。
JavaScriptテストは音声と画面の代替オブジェクトを使って再生制御を確認するため、
実ブラウザでの見た目や聞こえ方の確認は別途必要です。

Issue #16〜#20の画面操作は、Playwrightを用意した開発環境で次のように確認できます。
アプリ本体の起動にはPlaywrightは不要です。

```bash
.venv/bin/python -m pip install playwright==1.62.0 pypdf==6.20.1
.venv/bin/python -m playwright install chromium --only-shell
.venv/bin/python tests/browser_fingering.py
.venv/bin/python tests/browser_tab_editor.py
.venv/bin/python tests/browser_arrangement.py
.venv/bin/python tests/browser_project.py
.venv/bin/python tests/browser_export.py
```

ChromiumのOS依存ライブラリが不足する場合は、
`.venv/bin/python -m playwright install-deps chromium` で追加します（管理者権限が必要）。
`PLAYWRIGHT_BROWSERS_PATH` を指定してブラウザを保存した場合は、テスト実行時も同じ値を指定してください。

出力の実機テスト用ライブラリーはアプリ本体には不要です。
`EXPORT_ARTIFACTS=/tmp/guitar-export-check` を指定して `tests/browser_export.py` を実行すると、
プレビュー画像・PDF・MusicXMLをそのフォルダーに残します。

MuseScore 4.7.5を用意すると、読み戻し照合も再実行できます（通常の単体テストでは起動しません）。

```bash
.venv/bin/python tests/verify_export_musescore.py /path/to/musescore --output /tmp/guitar-muse-check
# Linuxの画面なし環境・AppImage展開版では --offscreen を追加
```

公式XSDも検証する場合は、開発環境に `lxml==6.1.3` を入れ、
[MusicXML 4.0 schema](https://github.com/w3c/musicxml/tree/v4.0/schema) の
`musicxml.xsd`、`xml.xsd`、`xlink.xsd` を同じフォルダーに置きます。
上のコマンドに `--schema /path/to/musicxml.xsd` を追加すると、読み込み前にスキーマを検証します。
